# 林小呆

面向消费者的 AI 外卖决策助手：用自然语言表达预算、口味和时间，系统从渠道商品中筛选、推荐并承接下单与配送追踪。

## 当前能力

- 顾客注册、登录与安全会话
- 依据人数、预算、口味、忌口、销量与配送时间推荐渠道中的真实商品
- 区分“商品价预算”和“到手价预算”，到手价会将配送费纳入硬筛选
- 推荐卡透明展示商品价、配送费、预计到手价、优惠与渠道数据新鲜度
- 商品优先的推荐卡：先呈现具体商品、销量、评分、送达时间与主加购操作，渠道和门店作为来源信息
- 情境化点餐首屏：根据当前餐段、已连接门店、配送地址与个人味觉偏好生成一键场景，预算、口味和盲盒操作在首屏内完成
- 多候选决策速览：在展开商品卡前横向比较预计到手价、配送速度与销量优势，点击即可定位完整推荐理由
- 加购即时反馈：商品按钮就地确认加入结果、支持连续加份，并同步购物车数量；盲盒操作提供防重复与加载状态
- 搜索框提供可编辑的意图补全，可快速补充预算、排序、口味和配送时限，并支持键盘收起
- 无结果时根据当前条件生成一键恢复建议，可放宽预算、改为配送费另算或取消菜系/口味限制
- 顶部全局送达地址：支持最近地址切换与清理，并在购物车结算时自动带入
- 响应式对话导航：当前会话高亮、相对日期、平板图标态与手机端历史抽屉
- 渠道适配层：统一表达商品来源、同步状态、当前价格与原平台下单能力
- 持久化对话、订单、订单事件与菜品库存
- 完整购物车：数量调整、跨刷新恢复、起送价校验
- 两步式结算：先编辑购物车与送达信息，再集中核对商品、地址、备注和最终费用后提交
- 下单前实时核价：重新检查当前价格、配送费、库存、可售状态和起送门槛；变价需明确确认，缺货可更新购物车或让小呆推荐替代餐
- 配送地址就地校验、错误自动聚焦与常用地址记忆，提交失败时保留现场并给出可恢复提示
- 站内购物车、演示支付与订单管理；提交和支付提供忙碌状态，取消订单采用二次确认
- 已完成订单支持“再来一单”：复购前重新核对门店营业状态、商品可售性、实时库存、当前价格与配送费；已有购物车时先确认再替换
- 进行中订单优先的履约中心：同步预计送达、五阶段进度、完整事件记录，并自动刷新状态
- 配送实时状态卡：展示预计到达时刻、剩余时间、整体进度、下一节点、最近更新与配送员状态；手动同步失败时保留现有订单并提供重试
- 全局履约浮条：待支付或配送中的订单会持续显示在点餐主界面，突出下一步操作、预计送达与同步模式，并可一键返回订单详情
- 断网与服务异常恢复：全局提示商品、价格或配送的新鲜度风险，保留购物车和现有订单，网络恢复后自动重新同步，并为所有 API 请求提供超时与可恢复错误文案
- 配送渠道签名回调：校验渠道授权、门店绑定与 HMAC-SHA256 签名，幂等写入状态、ETA、骑手和轨迹链接，并拒绝状态倒退或过期消息
- 演示渠道会自动推进确认、制作、取餐、配送和完成，并明确标注不会真实扣款
- 已授权渠道可切换为平台订单回调、骑手信息和位置 H5 同步
- “心动菜单”收藏夹：保存整套搭配、按场景分类、一键复购，并检测当前价格和可售状态
- “今日食欲人格”互动测试：3 道直觉题生成个性吃饭签，并将结果直接转成推荐条件
- 食欲人格结果支持系统分享或复制文案，兼顾趣味体验与自然传播
- 餐后“回味打卡”：用心情与味觉标签沉淀真实反馈，支持更新且不会重复计数
- 个人味觉档案与成长等级；正向回味会参与后续推荐排序，形成越用越懂你的闭环
- “味觉探险护照”：完成真实订单即可解锁菜系印章、累计探险分，并参与每周 3 种菜系不重样挑战
- 未解锁印章可一键交给小呆生成下一餐推荐；首次解锁提供一次性庆祝反馈，形成探索—消费—收藏闭环
- “一周饭感周报”：按中国自然周回顾完成订单、风味跨度、饭点角色与餐后心情，并支持查看过去 12 周
- 周报自动生成下一周味觉任务并可直接发起推荐；分享文案默认排除金额、餐厅、地址等隐私信息
- “饭搭子选餐房”：按当前口味生成 3 家候选，通过 6 位口令邀请朋友实时加入、一人一票并可改票
- 选餐房自动识别平票与领先共识，结果可一键带回点餐；支持系统分享并在不可用时回退到复制邀请
- SQLite 本地数据库，使用 `DATABASE_URL` 可迁移至 PostgreSQL

## 本地运行

首次安装后端依赖：

```bash
python -m venv .venv
.venv\\Scripts\\python -m pip install -r backend/requirements.txt
```

启动后端：

```bash
.venv\\Scripts\\python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --reload
```

另开一个终端启动前端：

```bash
npm install
npm run dev
```

访问 `http://127.0.0.1:5173`。首次启动会创建 `backend/linxiaodai.db` 并写入演示餐厅与菜品。

用户演示账号：`demo@linxiaodai.com` / `demo123`

## Docker 运行

```bash
docker compose up --build
```

前端为 `http://127.0.0.1:5173`，API 文档为 `http://127.0.0.1:8000/docs`。

## 配送渠道回调适配

为已授权渠道配置专用密钥（渠道 key 中的非字母数字字符需替换为下划线并转为大写）：

```bash
PROVIDER_MEITUAN_WEBHOOK_SECRET=replace-with-a-strong-secret
```

渠道将原始 JSON 请求体以 HMAC-SHA256 计算十六进制摘要，并请求：

```text
POST /api/provider-callbacks/{provider_key}/orders/{order_id}
X-Provider-Signature: sha256={hex_digest}
```

回调体支持 `status`、`externalOrderId`、`trackingUrl`、`estimatedArrivalAt`、`riderName`、`riderVehicle`、`riderStatus`、`note` 与 `occurredAt`。也可使用 `PROVIDER_WEBHOOK_SECRET` 作为所有渠道的回退密钥；生产环境建议始终使用渠道专用密钥并定期轮换。

## 生产落地的下一步
